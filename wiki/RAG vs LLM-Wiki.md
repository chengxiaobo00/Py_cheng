# RAG vs LLM-Wiki

## 概述

两种 AI 辅助知识管理范式的横向对比：检索增强生成 (RAG) 与 Karpathy 的 LLM-Wiki 方法论。

## 核心差异

| 维度 | RAG | LLM-Wiki |
|------|-----|----------|
| **AI 角色** | 检索助手 | 知识管理员 |
| **知识状态** | 被动索引 | 主动结构化编译 |
| **查询方式** | 每次重新检索+综合 | 直接读取已综合的页面 |
| **积累效应** | 无沉淀 | 逐次增强（复利） |
| **跨引用** | 无 | 自动建立和更新 |
| **矛盾检测** | 无 | 主动标记 |
| **边际成本** | 恒定 | 递减 |
| **质量趋势** | 不稳定 | 随时间提升 |

## 成本公式

```
RAG:    每次查询成本 = 检索成本 + 综合成本 (线性不变)
LLM-Wiki: 每次查询成本 = 初始编译成本/N + 维护成本 (递减)
```

**盈亏平衡点**：约 5-10 次查询后，LLM-Wiki 开始显现经济优势。

## 概念比喻

| RAG | LLM-Wiki |
|-----|----------|
| 每次做饭重新认食材、学菜谱 | 建立可复用的烹饪体系 |
| 搜索引擎 | 维基百科 |
| 临时笔记 | 系统笔记 |
| 聊天机器人 | 知识合作者 |

## 何时用哪种

### 适合 RAG 的场景
- 一次性查询，不会再问第二遍
- 内容高度动态、频繁变更
- 数据量极大但结构松散

### 适合 LLM-Wiki 的场景
- 需要反复查询某个领域
- 需要系统理解和建立知识联系
- 长期积累、持续演进的知识体系

## 关键洞察

> "不要把 AI 当作更聪明的搜索引擎，而要把它当作永不疲倦的知识管理员。" — Karpathy
