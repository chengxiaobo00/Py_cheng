id="ss-hId-1" hid="ss-hId-1">前言</h2><p data-omnivore-anchor-idx="11">作为一位拥有一台 NAS 的普通玩家，自建一个本地音乐库是丰富家庭影音中不可或缺的一环。我也在个人博客《<a data-omnivore-anchor-idx="12" href="https://sspai.com/link?target=https%3A%2F%2Fwww.himiku.com%2Farchives%2Fbuild-my-music-library-service.html" target="_blank">我的音乐库解决方案</a>》一文中，简要地介绍了现阶段我在 NAS 上自建音乐库的一些方案。可无论是 Jel­lyfin、Emby 还是 Plex，它们都不是专门的音乐媒体程序。即便这些软件都具备播放音乐的功能，界面也十分美观，但它们的核心用途终究还是在视频播放上。因此，我也只建议同时有视频观看需求的朋友部署这类媒体程序，这样才不会在使用时因为程序有太多用不上的功能而感到困扰。</p><p data-omnivore-anchor-idx="13">后来，我又发现了一款开源的音乐服务器软件「<a data-omnivore-anchor-idx="14" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fnavidrome%2Fnavidrome%2F" target="_blank">Navidrome</a>」。只是相比御三家，Navidrome 的界面虽然采用的是 Material Design 设计，但就显示效果来看并不符合我个人的审美需求；网页端虽然全平台通用，但在移动设备上还是需要有一个 App 方便即开即用；即使兼容 Subsonic/Madsonic/Airsonic 等一系列音乐流媒体协议，但市面上的大部分支持这些协议的播放器都是英文，几乎没有汉化，用着也十分不趁手；更别说直到本文发布的现在，Navidrome 还是不支持外挂 LRC 歌词……</p><p data-omnivore-anchor-idx="15">如此这番批判下，想必你也能理解我为何没有及时安利 Navidrome 了。可现在推荐的原因又是什么呢？最近在网上冲浪的时候，看到群友推荐了一款国人开发的音乐播放器程序「音流」。界面符合国人审美，设计简洁，功能实用，间接性地解决了 Navidrome 不好看也不好用的痛点。因此，Navidrome 也就值得推荐给大家一试了。</p><p data-omnivore-anchor-idx="16"><strong data-omnivore-anchor-idx="17">以下操作均于搭载 DSM 7.2.1 的 DS220+ 中进行，Docker Compose 版本为 2.25.0。</strong></p><h2 data-omnivore-anchor-idx="18" id="ss-hId-2" hid="ss-hId-2">安装</h2><p data-omnivore-anchor-idx="19">首先，在 docker 文件夹中创建一个名为 <code data-omnivore-anchor-idx="20" class="hljs language-ebnf"><span data-omnivore-anchor-idx="21" class="hljs-attribute">navidrome</span></code> 的文件夹，并在其中再创建一个名为 <code data-omnivore-anchor-idx="22" class="hljs language-haskell language-ebnf"><span data-omnivore-anchor-idx="23" class="hljs-class"><span data-omnivore-anchor-idx="24" class="hljs-keyword">data</span></span></code> 的数据文件夹。</p><p data-omnivore-anchor-idx="25">接着，准备好若干音乐并上传至 NAS 中，复制该文件夹的<strong data-omnivore-anchor-idx="26">完整路径</strong>。例如 <code data-omnivore-anchor-idx="27" class="hljs language-awk language-dts"><span data-omnivore-anchor-idx="28" data-omnivore-anchor-idx="31" class="hljs language-ebnf"><span data-omnivore-anchor-idx="32" class="hljs-attribute">root</span></code> 用户运行，因此需要指定容器的运行用户。群晖管理员用户一般是 <code data-omnivore-anchor-idx="33" class="hljs language-angelscript language-css"><span data-omnivore-anchor-idx="34" class="hljs-number">1026</span>:<span data-omnivore-anchor-idx="35" class="hljs-number">100</span></code> ，也可以使用当前用户登录 SSH 终端后，输入 <code data-omnivore-anchor-idx="36" class="hljs language-applescript language-ebnf"><span data-omnivore-anchor-idx="37" class="hljs-built_in">id</span> username</code> 查询。例如我的群晖用户名是 <code data-omnivore-anchor-idx="38" class="hljs language-ebnf"><span data-omnivore-anchor-idx="39" class="hljs-attribute">mikusa</span></code> ：</p><pre data-omnivore-anchor-idx="40"><code data-omnivore-anchor-idx="41" class="hljs language-routeros language-angelscript">$ id mikusa
<span data-omnivore-anchor-idx="42" class="hljs-attribute">uid</span>=1026(mikusa) <span data-omnivore-anchor-idx="43" class="hljs-attribute">gid</span>=100(users) <span data-omnivore-anchor-idx="44" class="hljs-attribute">groups</span>=100(users),101(administrators),65537(docker)</code></pre><p data-omnivore-anchor-idx="45">那么，在创建 <code data-omnivore-anchor-idx="46" class="hljs language-css"><span data-omnivore-anchor-idx="47" class="hljs-selector-tag">compose</span><span data-omnivore-anchor-idx="48" class="hljs-selector-class">.yaml</span></code> 时，就在 <code data-omnivore-anchor-idx="49" class="hljs language-dockerfile language-ebnf"><span data-omnivore-anchor-idx="50" class="hljs-keyword">user</span></code> 配置中填写 <code data-omnivore-anchor-idx="51" class="hljs language-angelscript language-css"><span data-omnivore-anchor-idx="52" class="hljs-number">1026</span>:<span data-omnivore-anchor-idx="53" class="hljs-number">100</span></code>。</p><p data-omnivore-anchor-idx="54"><strong data-omnivore-anchor-idx="55">如果实在是无法确定或者懒得查，那就填 </strong><code data-omnivore-anchor-idx="56" class="hljs language-angelscript language-css"><span data-omnivore-anchor-idx="57" class="hljs-number">1000</span>:<span data-omnivore-anchor-idx="58" class="hljs-number">1000</span></code><strong data-omnivore-anchor-idx="59">。</strong></p><p data-omnivore-anchor-idx="60">随后，在电脑上创建一个名为 <code data-omnivore-anchor-idx="61" class="hljs language-css"><span data-omnivore-anchor-idx="62" class="hljs-selector-tag">compose</span><span data-omnivore-anchor-idx="63" class="hljs-selector-class">.yaml</span></code> 的文本，填入以下内容：</p><pre data-omnivore-anchor-idx="64"><code data-omnivore-anchor-idx="65" class="hljs language-dts language-yaml"><span data-omnivore-anchor-idx="66" class="hljs-symbol">services:</span>

<span data-omnivore-anchor-idx="68" class="hljs-symbol">    image:</span> deluan/navidrome:latest
<span data-omnivore-anchor-idx="69" class="hljs-symbol">    container_name:</span> navidrome
<span data-omnivore-anchor-idx="70" class="hljs-symbol">    user:</span> <span data-omnivore-anchor-idx="71" class="hljs-number">1026</span>:<span data-omnivore-anchor-idx="72" class="hljs-number">100</span> <span data-omnivore-anchor-idx="73" class="hljs-meta">#用户id</span>
<span data-omnivore-anchor-idx="74" class="hljs-symbol">    ports:</span>

<span data-omnivore-anchor-idx="78" class="hljs-symbol">    volumes:</span>
      - ./data:/data <span data-omnivore-anchor-idx="79" class="hljs-meta">#数据路径</span>
      - <span data-omnivore-anchor-idx="80" class="hljs-meta-keyword">/volume1/</span>media/music:/music:ro <span data-omnivore-anchor-idx="81" class="hljs-meta">#音乐路径</span>

      <span data-omnivore-anchor-idx="96" class="hljs-meta"># - HTTPS_PROXY=http:<span data-omnivore-anchor-idx="97" class="hljs-comment">//proxy:port</span></span>
<span data-omnivore-anchor-idx="98" class="hljs-symbol">    restart:</span> unless-stopped</code></pre><p data-omnivore-anchor-idx="99">你也可以在创建项目的时候选择「创建 docker-compose.yml」，粘贴上述配置，免去上传的步骤。</p><p 就可以做到开箱即用。</p><p data-omnivore-anchor-idx="152">在安装 Navidrome 时配置的 Spotify 和 Last.fm，最终会让艺术家页可以显示头像和简介等相关信息。</p><figure data-omnivore-anchor-idx="153"><img data-omnivore-anchor-idx="154"
