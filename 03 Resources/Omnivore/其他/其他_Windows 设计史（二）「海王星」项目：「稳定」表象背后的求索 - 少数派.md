data-omnivore-anchor-idx="13">我在上期结尾写道，「Windows 95 发布后，接下来几年内 Windows 的主要界面、设计风格等也稳定了下来」。但「稳定」表象的背后，在微软内部对于 Windows 界面设计的探索一直没有停止。<strong data-omnivore-anchor-idx="14">这些探索旨在融合当时蓬勃发展的网络技术，构建一个以任务为导向，以「页面」概念替代「桌面」和「窗口」设计的用户界面。</strong>不过由于这些探索最终无果而终，这段历史最终湮没在了时间的长河中，并被后来 Windows XP 的成功所掩盖。但回看这段历史，其中的一些想法不仅被后来的 Windows 所采用，且对现在的用户界面设计仍不失借鉴意义。</p><blockquote data-omnivore-anchor-idx="15"><p data-omnivore-anchor-idx="16">由于关于这段历史的资料比较有限，如有疏漏之处还请各位谅解并及时指出，也谢谢各位对本系列的支持。</p></blockquote><h2 data-omnivore-anchor-idx="17" id="ss-hId-1" hid="ss-hId-1">「操作系统网页化」？</h2><p data-omnivore-anchor-idx="18">（如果方便的话）请跟我做一个实验：打开你手上的 Windows，随便找一个 html 或 htm 网页文件（内容最好不要太复杂），将其文件后缀改为 hta，直接点击打开，发现网页中的内容能正常显示，而且网页似乎变为了一个独立的程序。<sup data-omnivore-anchor-idx="25">这个小小的 hta 文件，就是微软在上世纪末进行的「操作系统网页化」试验的一个遗产。</p><p data-omnivore-anchor-idx="26">1997 年 9 月，Internet Explorer 4 发布，同时还为 Windows 引入了一个叫「Windows 桌面更新」的功能。这个更新在 Win95 和 NT 4.0 中为可选更新，在 Windows 98 中由于 IE4 默认安装，该更新为内置功能。</p><p data-omnivore-anchor-idx="27">乍一看你可能不知道这玩意是干什么的，实际上这个更新的目的的就是加强 IE 与 Windows 间的集成。反映到设计上就是，Windows 文件资源管理器采用了类似 IE 浏览器的界面，任务栏上引入了工具栏和放置快捷方式的「快速启动」栏，以及「活动桌面（Active Desktop）」 和「频道栏（Channel Bar）」。「活动桌面」允许用户将 Web 项目（比如网页）设置为壁纸，并允许用户在桌面上与这些 Web 项目直接交互（现在许多动态桌面软件也有类似的功能）。「频道栏」可用于实时接收并在桌面上显示来自网站的信息。</p><figure Windows</figcaption></figure><p data-omnivore-anchor-idx="34">为什么微软这个时候这么执着于 Windows 与浏览器的集成？联系当时的历史背景就会发现，当时正是「第一次浏览器大战<sup data-omnivore-anchor-idx="35" href="" footnote-id="2" data-title="指的是自20世纪90年代初万维网浏览器(WorldWideWeb)推出以来，Mosiac 及后来的 Netscape Navigator（网景浏览器）、微软IE等浏览器的市场竞争。">2<div data-omnivore-anchor-idx="36"><p data-omnivore-anchor-idx="37">指的是自20世纪90年代初万维网浏览器(WorldWideWeb)推出以来，Mosiac 及后来的 Netscape Navigator（网景浏览器）、微软IE等浏览器的市场竞争。</p></div></sup>」激烈进行的时期，据说网景（代表产品就是风光一时的网景浏览器）创始人马克·安德森曾夸下海口：「未来，在网景面前，Windows 将被简化为一堆设计拙劣的设备驱动程序的集合。」网景这样的野心不能不说会刺激到微软。为与网景浏览器竞争，微软加速了 IE 与 Windows 间的集成，借 Windows 的力量提升 IE 浏览器的市场份额。同时随着互联网技术的蓬勃发展，人们都对互联网展现出的的巨大潜力充满期待。正是在这样的背景下，微软开始了「操作系统网页化」试验，以在操作系统中充分利用互联网的特性。上文提到的 hta 文件，就是随 IE5 发布引入的新特性。当时该文件格式也被用到了一些系统文件中，比如欢迎程序等。</p><p data-omnivore-anchor-idx="38">不过，微软似乎没有料想到这些举措的副作用：当 IE 浏览器在后来渐渐失去了市场份额乃至停止支持时，如何将其从 Windows 中剥离就成了不小的挑战。但这不是本文的重点，下文我们要关注的是，这些意在提升自带浏览器地位的举措，将如何导向一场旨在重构 Windows 用户界面的试验。</p><h2 data-omnivore-anchor-idx="39" id="ss-hId-2" hid="ss-hId-2">从「RedShark（红鲨）」到「Neptune（海王星）」</h2><p data-omnivore-anchor-idx="40">1998 年，Ben Slivka、Joe Belfiore、Steve Capps 等共 15 名微软员工组成了一个叫「RedShark」的项目团队（据雷蒙德·陈，这个名字来自于办公室里的一个小型充气红鲨玩偶），负责构想 Windows 新的用户界面。这个界面的核心理念是「软件即服务」，旨在打造超越 Windows 和 Internet 的以人为本的计算体验，具体思想如下：</p><blockquote data-omnivore-anchor-idx="41"><ol data-omnivore-anchor-idx="42"><li data-omnivore-anchor-idx="43">所有数据都存储在服务器上；</li><li data-omnivore-anchor-idx="44">计算机只是代码和数据的安全缓存；</li><li data-omnivore-anchor-idx="45"><strong data-omnivore-anchor-idx="46">项目</strong>是关键的组织原则（团队认为，人们所做的大部分工作都是在一个<strong data-omnivore-anchor-idx="47">项目</strong>的背景下进行的：比如，一对夫妇计划夏威夷度假；一群家长和老师计划 PTSA（家长-教师-学生联谊会）活动；或者涉及多家公司、律师事务所、银行家的复杂金融交易和顾问，等等）；</li><li data-omnivore-anchor-idx="48">可以很好地「离线」工作。</li></ol><p data-omnivore-anchor-idx="49">（Ben Slivka 在其<a data-omnivore-anchor-idx="50" href="https://sspai.com/link?target=https%3A%2F%2Fbenslivka.com%2F2020%2F11%2F20%2Fbefore-slack-and-teams-the-windows-service-1998%2F" target="_blank">文章</a>中回顾该项目时，借用了 Microsoft Teams 和 Slack 来说明该项目的愿景。他表示：「Microsoft Teams 和 Slack 都走在实现我们当年愿景的道路上，但两者都有复杂性和局限性。我们的主要见解是：<strong data-omnivore-anchor-idx="51">项目</strong>应该是组织原则，而不是<strong data-omnivore-anchor-idx="52">团队</strong>。」）</p></blockquote><p data-omnivore-anchor-idx="53">那么界面应该如何设计呢？该团队提出界面应<strong data-omnivore-anchor-idx="54">按照页面组织内容，全屏且无窗口管理，具有统一的搜索/历史记录，支持多用户和漫游功能</strong>。</p><p data-omnivore-anchor-idx="55">「RedShark」提出的概念最终在代号为「Neptune（海王星）」的 Windows 版本中进行了实践。</p><p data-omnivore-anchor-idx="56">以下展示了一些该项目的概念演示。可以看到，这一界面借鉴了网络浏览器中的一些界面设计概念，比如导航栏、主页等。</p><figure data-omnivore-anchor-idx="57"><img data-omnivore-anchor-idx="58" data-omnivore-anchor-idx="69" id="ss-hId-3" hid="ss-hId-3">神秘的「海王星」</h2><p data-omnivore-anchor-idx="70">如果不是专门了解过 Windows 发展史的人，可能会对「Neptune」这个版本比较陌生。确实，这个版本出现时间很短，目前已公开的也就只有一个构建。可以说，在 Windows 的发展史中，「Neptune」是一个神秘的存在。但放眼整个 Windows 的发展历程，它又非常重要，其中的一些功能设计对当时和后来的 Windows 版本影响深远。</p><p data-omnivore-anchor-idx="71">该项目本来旨在接替 Windows 98（但它基于 NT 内核，而非 Win98 采用的 9x 内核），其中的一些功能又被同时期的 Windows Me 所采用，而它自身又与旨在继承 Windows 2000 的 Odyssey 项目（这个项目存在感更低，至今一个版本都没有公开）合并，组成了代号为「Whistler」的项目。</p><p data-omnivore-anchor-idx="72">「Neptune」中的「活动中心」设计，就是对上述想法的一个实践。<sup data-omnivore-anchor-idx="73" href="" footnote-id="3" data-title="实际上 Neptune 和 WinMe 的开发是相互交织的，所以有些功能可能是先在 WinMe 上实现，后移植到 Neptune 上的。因此实际版本中 Neptune 上的活动中心使用的是 WinMe 的 Millennium 代号。">3<div data-omnivore-anchor-idx="74"><p data-omnivore-anchor-idx="75">实际上 Neptune 和 WinMe 的开发是相互交织的，所以有些功能可能是先在 WinMe 上实现，后移植到 Neptune 上的。因此实际版本中 Neptune 上的活动中心使用的是 WinMe 的 Millennium 代号。</p></div></sup></p><p data-omnivore-anchor-idx="76">「活动中心」是一种<strong data-omnivore-anchor-idx="77">以任务为中心</strong>的新用户界面（与上文提到的<strong data-omnivore-anchor-idx="78">「项目」</strong>概念相似，都是从用户所要完成的事情为出发点），以 HTML 和 Win32 API 组合编写，基于一个名为 Mars 的 Web 框架运行。科技评论员 Paul Thurrott 对「活动中心」有详细的<a data-omnivore-anchor-idx="79" href="https://sspai.com/link?target=https%3A%2F%2Fwww.itprotoday.com%2Fwindows-server%2Factivity-centers-preview" target="_blank">描述</a>，它计划包括照片中心、音乐中心、游戏中心、帮助中心、家庭网络配置中心和自动更新（AutoUpdate）页面等，基于被称为「感应式导航」的设计原则，具体原则如下：</p><blockquote data-omnivore-anchor-idx="80"><ul data-omnivore-anchor-idx="81"><li data-omnivore-anchor-idx="82">为几个主要领域的所有任务提供无缝的用户体验。</li><li data-omnivore-anchor-idx="83">以<strong data-omnivore-anchor-idx="84">任务</strong>为导向，根据任务目标而不是工具来表述选项。</li><li data-omnivore-anchor-idx="85">将用户聚焦于每个「页面」的单个任务上，并清楚地说明该焦点。</li><li data-omnivore-anchor-idx="86">始终使下一个导航步骤显而易见。</li><li data-omnivore-anchor-idx="87">在主要任务以外枚举操作的选项。</li></ul></blockquote><p data-omnivore-anchor-idx="88">「活动中心」包含一个「起始页」（用户可以通过「活动桌面」功能将其设置为桌面），其中包含一些推荐任务（比如查看邮箱、浏览网络等），最近程序/文件等。</p><p data-omnivore-anchor-idx="89">每个中心的主页会提供主要任务。例如，照片中心会提供使用扫描仪或数码相机获取图像、查看系统上已存储的图像或搜索图片的链接。用户也能够自定义主要任务。</p><p data-omnivore-anchor-idx="90">除了主要任务，各个中心还提供次要任务页面，为用户提供完成单个任务的明显步骤。任务页面上的标题通常会是一个问题（如：您想使用 MicroTek ScanMaker 6i 扫描图像吗？）或描述（选择要使用 Microsoft PhotoDraw 2001 进行编辑的图片）。无论任务如何呈现，它都会使用明显、简洁的语句准确地告诉用户该页面的用途。</p><p data-omnivore-anchor-idx="91">同时，各个中心都包含一个「导航栏」，用户可以借助导航栏定位到所需页面，或者回到主页。</p><figure data-omnivore-anchor-idx="92"><img data-omnivore-anchor-idx="93" 最后感叹说：「我们实在太超前于时代了」。而现实情况是，当时的底层技术还不足以支持类似「活动中心」界面的实现。</p><p data-omnivore-anchor-idx="109">Windows Me 的最终版本部分实现了「活动中心」的一些设计。帮助中心在 Windows Me&nbsp;中更名为「帮助与支持」，音乐中心的部分设计被应用到了新的 Media Player 7
