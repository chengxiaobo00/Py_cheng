data-omnivore-anchor-idx="19">使用离线账户</h3><p data-omnivore-anchor-idx="20">Windows 10 在初次使用的时候可以跳过网络连接设置，选择「离线账户」。这样可以避免微软账户的一些设置，但也会导致一些功能无法使用。而 Windows 11 在安装时──至少从 UI 来看──会强制要求连接网络并登录 Microsoft 账户。</p><p data-omnivore-anchor-idx="21">如果你只想通过离线账户使用，或碰上微软服务抽风偏偏又无法登录的情况，在这一步可通过&nbsp;<code data-omnivore-anchor-idx="22" class="hljs language-dos language-mipsasm"><span data-omnivore-anchor-idx="23" class="hljs-built_in">Shift</span> + F10</code>&nbsp;调出命令行，输入&nbsp;<code data-omnivore-anchor-idx="24" class="hljs language-livescript language-moonscript">oobe<span data-omnivore-anchor-idx="25" class="hljs-string">\BypassNRO</span></code>。命令执行后系统将自动重启，此后初始化过程中的网络配置会额外出现「我没有 Internet 连接」选项，再点击「继续执行受限设置」后续即可配置离线账户。而如果你已经联网，看到强制要求登录 Microsoft 账户界面后才寻找使用离线账户账户的方法，此时只通过上面的命令是不够的——至少从我唯一的一次经历来看输入命令后重启后仍然会自动配置好网络，此时则需要先输入&nbsp;<code data-omnivore-anchor-idx="26" class="hljs language-ebnf"><span data-omnivore-anchor-idx="27" class="hljs-attribute">devmgmt</span></code>&nbsp;打开设备管理器、禁用无线网卡，然后再输入&nbsp;<code data-omnivore-anchor-idx="28" class="hljs language-livescript language-moonscript">oobe<span data-omnivore-anchor-idx="29" class="hljs-string">\BypassNRO</span></code>。</p><p data-omnivore-anchor-idx="30">总之这个命令执行后系统将自动重启，此后初始化过程中的网络配置会额外出现「我没有 Internet 连接」选项，再点击「继续执行受限设置」后续即可配置离线账户。而如果你已经联网，看到强制要求登录 Microsoft 账户界面后才寻找使用离线账户账户的方法，此时只通过上面的命令是不够的——至少从我唯一的一次经历来看输入命令后重启后仍然会自动配置好网络，此时则需要先输入 <code data-omnivore-anchor-idx="31" class="hljs language-ebnf"><span data-omnivore-anchor-idx="32" class="hljs-attribute">devmgmt</span></code> 打开设备管理器、禁用无线网卡，然后再输入 <code data-omnivore-anchor-idx="33" class="hljs language-livescript language-moonscript">oobe<span data-omnivore-anchor-idx="34" class="hljs-string">\BypassNRO</span></code>。</p><p data-omnivore-anchor-idx="35">截至目前通过这些额外的手段还是能够使用离线账户，但微软如此收窄用户选择的空间，很难不让人揣测其意图，甚至给人留下一种不断侵蚀用户隐私和选择权的糟糕印象，毕竟在线账户只会让微软更轻松地收集各种用户数据，包括使用习惯、偏好设置等个人信息，而这些收集行为也不只在本设备，通过在线账户，微软也能更轻松地跟踪用户在不同设备间的行为，构建更完整的用户画像……收集到的数据则可以用于精准投放广告、出售给第三方广告商、通过与其他微软服务的集成二次扩大数据共享范围。</p><p data-omnivore-anchor-idx="36">要知道 Microsoft 账户隐私设置界面着实复杂，迈过离线账户的坎，后面想要完全控制自己的隐私选项难度就不低了。</p><h3 data-omnivore-anchor-idx="37">合理配置更新</h3><p data-omnivore-anchor-idx="38">除了预装系统的 OEM macOS，兼容性最好的 Windows 在更新上也更容易受兼容性带来的多样性所困，从而很难实现更新行为和质量的一致性。这也是为什么每每听闻 Windows 更新问题时，总有人说「从来没遇到过」，也总有另一些人抱团抱怨仿佛 Windows 都快完全不可用了那般。</p><p data-omnivore-anchor-idx="83">其实如今没必要过于抵制 Windows data-omnivore-anchor-idx="237">电源设置</h3><p data-omnivore-anchor-idx="238">「Wintel 联盟」现在似乎已经很少提起，当初意图取代 IBM 公司在个人计算机市场上的主导地位，直至现在 Microsoft 和 Intel 的合作依然紧密。Intel 新大小核处理器在 Windows 10 上有许多调度问题促使其用户不得不选择 Windows 11。</p><p data-omnivore-anchor-idx="239">如果你在电源设置中发现缺少某些设置项目，除了一个个查注册表，更方便的方法是通过 <a data-omnivore-anchor-idx="240" href="https://sspai.com/link?target=https%3A%2F%2Fforums.guru3d.com%2Fthreads%2Fwindows-power-plan-settings-explorer-utility.416058%2F" target="_blank"><code data-omnivore-anchor-idx="241" class="hljs language-ebnf"><span data-omnivore-anchor-idx="242" class="hljs-attribute">PowerSettingsExplorer</span></code></a> 这个仅调用 <a data-omnivore-anchor-idx="243" href="https://sspai.com/link?target=https%3A%2F%2Flearn.microsoft.com%2Fen-us%2Fwindows%2Fwin32%2Fpower%2Fpower-management-functions%3Fredirectedfrom%3DMSDN" target="_blank">Power Management Functions</a> 接口的小工具来调出那些被隐藏的选项。在 Windows 11 中与大小核调度策略有关的隐藏高级电源设置有：</p><ul data-omnivore-anchor-idx="244"><li data-omnivore-anchor-idx="245">生效的异类策略</li><li data-omnivore-anchor-idx="246">异类线程调度策略</li><li data-omnivore-anchor-idx="247">异类短时间线程调度策略</li></ul><p data-omnivore-anchor-idx="248">在「高性能」电源计划中，这三个的设置按顺序是「0 - 自动 - 自动」，调度策略是「大核 &gt; 小核 &gt; 大核超线程」；如果将后两个设置同时设为「高性能处理器」，那么调度策略变为「大核 &gt; 大核超线程」。总体而言异类策略 0 优先使用大核，对应的异类策略 1 优先使用小核。异类策略 4 比较奇怪，它是「节能」电源计划的默认设置，但是在烤鸡、游戏挂机等测试场景大小核调度策略几乎和「高性能」一致，怀疑是高负载场景积极调度、中低负载再节能的策略。</p><p data-omnivore-anchor-idx="249">其实预设的几种电源计划均挺符合直觉的，没必要过于纠结。即便有极端省电需求也不建议完全小核优先，其实该设置中的所谓「高效处理器」也就是小核还真未必比限制后的大核能效比高。看看对功耗更加敏感的移动端，都有越来越多大核的势头，乃至天玑的全大核构想。当然移动端大核甚至还没够到桌面端的小核，不能简单横向比较。不过时至今日我依然对桌面端异构架构持保守态度。</p><p data-omnivore-anchor-idx="250">以上都是针对 Intel 新处理器的情况，对于 AMD 全大核处理器，Windows 11 的大小核调度反而引入额外问题导致游戏场景表现甚至不如 Windows 10。众所周知，锐龙 CPU 各核心都有成为 CPPC 属性，代表各个核心的「体质」，在 AMD 官方工具 Ryzen Master 中可以查看的金、银核心分别就是 CPPC 最高的两个核心，而 Windows 11 会将 CPPC 最低核心视为小核（高效处理器）进行调度。通过上述真正大小核的 Intel 处理器上观测的不同异类调度策略并在 AMD 全大核处理器上对应测试，发现 Windows 11 对 AMD 处理的调度的确遵循 N-1 个高性能处理器和 1 个高效处理器的策略。这样默认的调度策略会更不倾向调用所谓的小核，这种不对称可能会导致更多的跨核行为、特别是游戏场景频繁地 L3 缓存争用造成无端性能损失。</p><p data-omnivore-anchor-idx="251">之前的民间偏方，在 BIOS 开 PBO、XMP/EXPO 的同时顺手把 CPPC 关掉，或许也是由此而来。</p><p data-omnivore-anchor-idx="252">早在去年 UP 主 <code data-omnivore-anchor-idx="253" class="hljs language-gherkin language-julia"><span data-omnivore-anchor-idx="254" class="hljs-meta">@开心的托尔酱</span></code> 在视频 <a data-omnivore-anchor-idx="255" href="https://www.bilibili.com/video/BV1e94y1L7Ds/" target="_blank">关于Windows系统对AMD的负优化—异类线程调度</a> 就有提到这个问题。而在最近 AMD 在社区更新 <a data-omnivore-anchor-idx="256" href="https://sspai.com/link?target=https%3A%2F%2Fcommunity.amd.com%2Ft5%2Fgaming%2Fryzen-9000-series-community-update-gaming-performance%2Fba-p%2F704054" target="_blank">关于 Zen 5 游戏性能提升远不及理论的回应</a>，宣布 Windows 11 24H2 将通过优化「branch prediction」 来提升 AMD Zen3/4/5 系列处理器的性能表现，部分游戏甚至有 10% 以上提升，要知道 Zen 5 由于相较于前代提升过于微妙有被戏称「Zen 5%」，更有特例 <a data-omnivore-anchor-idx="257" href="https://www.bilibili.com/video/BV1fj421R7BJ/" target="_blank">5700X3D 在 Windows 11 上性能表现比 Windows 10 差 15%</a>……该说锐龙 CPU 首发一如既往地一言难尽呢、还是说与 Windows 合作不够紧密呢？</p><p data-omnivore-anchor-idx="258">当然，尽管 Windows 几个电源设置的预设符合直觉无需额外调整，电源设置里还是有很多可玩性的，例如不用重启调整 CPU 睿频参数等。具体不再展开，感兴趣可以参阅 <a data-omnivore-anchor-idx="259" href="https://www.bilibili.com/read/cv20805800/" target="_blank">Windows电源设置注释</a>。</p><h3 data-omnivore-anchor-idx="260">系统级备份</h3><p data-omnivore-anchor-idx="261">Windows 11 在「设置 &gt; 账户 &gt; Windows 备份」中可以设置包括文件、设置等备份选项，但似乎必须绑定微软账户使用，对于离线账户并不友好。且这种方法不支持备份系统。</p><p data-omnivore-anchor-idx="262">个人认为更好用的还属控制面板中的「备份和还原（Windows 7）」，不仅支持对系统分区全量备份，还支持制作系统镜像和系统恢复盘。虽然 Windows 在 <a data-omnivore-anchor-idx="263" href="https://sspai.com/link?target=https%3A%2F%2Fsupport.microsoft.com%2Fzh-cn%2Fwindows%2Fsystem-configuration-tools-in-windows-f8a49657-b038-43b8-82d3-28bea0c5666b" target="_blank">知识库</a> 中鼓励大家尽可能使用设置取代控制面板，无奈前者体验还偏偏不如后者。</p><p data-omnivore-anchor-idx="264">此外，<a data-omnivore-anchor-idx="265" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2FChuyu-Team%2FDism-Multi-language" target="_blank">Dism++</a> 也提供系统备份功能，同时支持不添加文件的增量备份（不算快照）。Dism（Deployment Imaging and Management）是 Windows 自带的一个工具，用于安装和维护 Windows 映像，Dism++ 只是将常用命令封装成 GUI 便于操作，并没有额外单独实现，这种备份也算是半官方方法。</p><p data-omnivore-anchor-idx="266">还有两个系统功能看似很好用但是我不推荐：一是系统检查点，它本意主要用于系统更新失败的回滚，很难说胜任纯粹的系统备份，对个人文件的行为很奇怪经常在回滚的时候搞得一团糟；而文件历史，它默认备份整个用户目录，需要自己一个个排除，且该功能仅放置于控制面板，微软对此也并不算上心，一个 bug 三五年不修。</p><p data-omnivore-anchor-idx="267">话说回来，目前单独备份系统的意义远不如备份文件，通过链接把一些应用的数据文件夹（例如微信保存的文件）link 到其他分区、外置存储乃至云端上，更多链接操作留到后续关于快捷创建链接的工具那一部分。</p><h3 data-omnivore-anchor-idx="268">BitLocker</h3><p data-omnivore-anchor-idx="269">Windows 11 正常要求硬件支持 TPM 2.0。TPM 芯片是一种安全加密处理器，包含多个物理安全机制以防篡改。BitLocker 会将专用密钥存储在 TPM 芯片内，在除了更改 TPM、BitLocker 检测到 BIOS 或 UEFI 配置、关键操作系统启动文件或启动配置的更改之外的情况下，BitLocker 会自动解锁，用户登录无需进行任何额外交互即可解锁。无其他加密手段建议对系统盘开启 BitLocker，这已经是 Windows 集成最高、最无感的方式。</p><p data-omnivore-anchor-idx="270">关于几个关键问题：</p><blockquote data-omnivore-anchor-idx="271"><p data-omnivore-anchor-idx="272">如果真有换设备需求，但是事先忘记解锁 BitLocker，会导致无法访问数据吗？</p></blockquote><p data-omnivore-anchor-idx="273">不会。在创建加密的时候 BitLocker 同时会创建恢复密码，可以将其打印或存在安全位置。检测到硬件更改后 BitLocker 进入恢复模式，用户输入恢复密码可以重新访问数据。</p><blockquote data-omnivore-anchor-idx="274"><p data-omnivore-anchor-idx="275">备份工具是否支持 BitLocker 加密盘？</p></blockquote><p data-omnivore-anchor-idx="276">对于基于文件系统的备份方式来说，理论上解锁后 BitLocker 是透明的，先解锁再备份即可。对于分区的备份方式，理论上可以不解锁整个区拷走，但是加密后不知道哪一部分是空的会导致备份文件更大且不好压缩，虽说 BitLocker 通过长长一串恢复密码也可以离线挂载，但不建议盲目还原。</p><blockquote data-omnivore-anchor-idx="277"><p data-omnivore-anchor-idx="278">BitLocker 是否会影响性能？</p></blockquote><p data-omnivore-anchor-idx="279">理论上会，但实际上体感不明显。别单看开 BitLocker 后硬盘读写速度有的下降超 10%，解密过程应是压力越大损耗越明显，所以不能根据硬盘测速这一极端压力情况下的性能损耗来界定 BitLocker 的性能损耗。</p><blockquote data-omnivore-anchor-idx="280"><p data-omnivore-anchor-idx="281">BitLocker 闭源，微软可以添加后门，如何保证安全？</p></blockquote><p data-omnivore-anchor-idx="282">你说得对，可以尝试开源方案 <a data-omnivore-anchor-idx="283" href="https://sspai.com/link?target=https%3A%2F%2Fveracrypt.eu%2Fen%2FDocumentation.html" target="_blank">VeraCrypt</a>，支持 Windows 11 系统加密，在普通分区加解密上还提供更好的跨平台支持，但是 VeraCrypt 不支持 TPM 且由于理念不合永远不会支持，在和 Windows 集成上肯定也不如 BitLocker 无感。看你愿不愿意拿所谓的安全换便利了。</p><h3 data-omnivore-anchor-idx="284">微软电脑管家</h3><p data-omnivore-anchor-idx="285">平心而论，这个软件本身并没有什么问题，但是大陆用户对「电脑管家」的 PTSD、早期仅在中国区推送和不事先提醒地静默安装才是其被人诟病的原因。</p><p data-omnivore-anchor-idx="286">后来，我的区域美国、语言英语的 data-omnivore-anchor-idx="503">MacBook 触控板和妙控板凭借着超大的触控面积、以假乱真的震动体验和 macOS 软硬结合，造就了曾经以及当下最优秀的触控板体验。许多 macOS 用户或许和我一样并不愿意使用鼠标，而是更倾向于触控板。其中稍微有些弯弯绕绕就属 macOS 的三指拖拽，如此好用的功能就藏在辅助功能里。</p><p data-omnivore-anchor-idx="504">当然随着微软给出精确式触控板的驱动和建议硬件规格，也体现出 Windows 对于触控板的上心，目前绝大多数 Windows 设备触控板也都支持精确式触控板，相当一部分产品日用体验已足够优秀。可惜的是即便系统对于多点触控的支持已经覆盖从二指到四指，但是三指和四指滑动手势略有重合且使用频率不高，Windows 也没有给出类似 macOS 的三指拖拽功能。</p><p data-omnivore-anchor-idx="505">好在可以通过插件 <a data-omnivore-anchor-idx="506" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2FClementGre%2FThreeFingerDragOnWindows" target="_blank">ThreeFingerDragOnWindows</a> 在 Windows 上实现 macOS 的三指拖拽，依赖 <code data-omnivore-anchor-idx="507" class="hljs language-asciidoc language-css"><span data-omnivore-anchor-idx="508" data-omnivore-anchor-idx="510"><li data-omnivore-anchor-idx="511">GitHub：<a data-omnivore-anchor-idx="512" data-omnivore-anchor-idx="513">Wiki: <a data-omnivore-anchor-idx="514" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2FAutoDarkMode%2FWindows-Auto-Night-Mode%2Fwiki" 支持通过设定固定时间或跟随该定位的日出日落时间自动切换深色模式，同时可以自定义深色、浅色模式对应主题。</p><h3 data-omnivore-anchor-idx="517">Link Shell Extension - 快速管理文件链接</h3><ul data-omnivore-anchor-idx="518"><li data-omnivore-anchor-idx="519">官网：<a data-omnivore-anchor-idx="520" href="https://sspai.com/link?target=https%3A%2F%2Fschinagl.priv.at%2Fnt%2Fhardlinkshellext%2Flinkshellextension.html" target="_blank">Link Shell Extension</a></li></ul><p data-omnivore-anchor-idx="521">在前文提到：</p><blockquote data-omnivore-anchor-idx="522"><p data-omnivore-anchor-idx="523">目前单独备份系统的意义远不如备份文件，通过链接把一些应用的数据文件夹（例如微信保存的文件）link 到其他分区、外置存储乃至云端上……</p></blockquote><p data-omnivore-anchor-idx="524">所谓「链接」，在文件系统中指的是软链接（符号链接）和硬链接──两种创建文件引用的方法。软链接（符号链接）是指向另一个文件或目录的路径，可以跨文件系统，类似于快捷方式；如果原文件被删除，软链接会失效。硬链接是直接指向文件数据的引用，两个文件共享相同的物理数据块，它们的内容完全一致，删除一个硬链接并不会影响到文件的实际数据，只有所有硬链接都删除时，数据才会被清除。硬链接只能在同一文件系统中创建，其实文件管理器上的几乎所有文件都可以被看作是硬链接。</p><p data-omnivore-anchor-idx="525">更详细关于链接的介绍可以参阅少数派文章 <a data-omnivore-anchor-idx="526" href="https://sspai.com/post/66834" target="_blank">符号链接、硬链接及其在 Windows 上的应用举例</a>。我对 Link Shell Extension 的初识也正是在这篇文章中。一个最常见的案例是，对于 <s data-omnivore-anchor-idx="527">小而美</s> 微信可以将其 Files 文件夹移动至 OneDrive，然后通过符号链接将其链接回原位置，这样既可以保证微信正常运行，又可以实现微信保存的文件备份。该插件的智能多版本硬链接功能会自动分析和前一次的差异并对不变的内容创建硬链接，实现增量备份，但该功能不能链接到外部存储，仅适合在同盘做备份版本管理。</p><p data-omnivore-anchor-idx="528">特别注意，少数派文章中介绍的「中键拖动」快速创建链接操作<strong data-omnivore-anchor-idx="529">不</strong>适用于 Windows 11，正确操作应当修改为使用<strong data-omnivore-anchor-idx="530">右键</strong>拖动。</p><h3
