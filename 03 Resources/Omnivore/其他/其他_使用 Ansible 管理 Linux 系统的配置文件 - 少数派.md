data-omnivore-anchor-idx="14"><h2 data-omnivore-anchor-idx="15" id="ss-hId-1" hid="ss-hId-1">前言</h2><p data-omnivore-anchor-idx="16">想必对于许多 Linux 用户来说，最无法割舍的东西大概是自己长年累月积攒的各种软件工具的配置文件（dotfiles），而如何系统性地管理这些文件，其实也已经有很多现成的方案，比如 <a data-omnivore-anchor-idx="17" href="https://sspai.com/link?target=https%3A%2F%2Fwww.gnu.org%2Fsoftware%2Fstow%2Fmanual%2Fstow.html" target="_blank">GNU/Stow</a> 和 <a data-omnivore-anchor-idx="18" href="https://sspai.com/link?target=https%3A%2F%2Fwww.chezmoi.io%2F" target="_blank">chezmoi</a>，可以将本来存放在系统各个角落的配置文件集中存放，并使用版本控制工具管理，当迁移到新的工作环境时，也可以十分方便地恢复自己原先的配置。</p><p data-omnivore-anchor-idx="19">不过这些 dotfiles 管理工具对我来说一直有两个主要痛点未被解决：</p><ul data-omnivore-anchor-idx="20"><li data-omnivore-anchor-idx="21">首先是只能管理当前用户家目录之中的文件，若遇到一些配置文件存放在 root 目录下的软件就无能为力了；</li><li data-omnivore-anchor-idx="22">再者是在部署配置文件之前，大多数时候还是需要手动安装所需的软件包，这些工具无法为我们自动安装需要的软件包。</li></ul><p data-omnivore-anchor-idx="23">因为 Linux 系统在设计之初就是针对多用户使用的，考虑到不是所有用户都有足够的权限来修改 root 目录和安装软件，像 Stow 和 chezmoi 这类软件不能实现以上的功能倒也情有可原。不过对于大多数个人电脑的使用情况，一个系统基本上只有一个主要用户，且这个用户都有使用 sudo 的权限，上面两个功能还是比较必要的。</p><p data-omnivore-anchor-idx="24">有关如何管理 root 目录中的文件，我发现了 <a data-omnivore-anchor-idx="25" href="https://sspai.com/link?target=https%3A%2F%2Fetckeeper.branchable.com%2F" target="_blank">etckeeper</a> 在某种意义上可以实现这种功能，但它的实现方式是将整个 <code data-omnivore-anchor-idx="26" class="hljs language-jboss-cli"><span data-omnivore-anchor-idx="27" class="hljs-string">/etc</span></code> 目录初始化成一个 git 目录，我觉得有些过于简单粗暴了。</p><p data-omnivore-anchor-idx="28">更进一步，使用 <a data-omnivore-anchor-idx="29" href="https://sspai.com/link?target=https%3A%2F%2Fnixos.org%2F" target="_blank">Nix</a> 搭配 <a data-omnivore-anchor-idx="30" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fnix-community%2Fhome-manager" target="_blank">Home Manager</a> 可以比较好地实现我需要的功能，但是需要我将包管理器切换到到 Nix，或是将系统整个换成 NixOS，还要从头学习 Nix 编程语言，迁移与学习成本都有些高了。</p><p data-omnivore-anchor-idx="31">那么有没有什么方法既可以让我不用离开 Arch 的舒适区，又可以比较方便地管理系统的配置文件，实现我想要的功能呢？最后我想到了 <a data-omnivore-anchor-idx="32" href="https://sspai.com/link?target=https%3A%2F%2Fwww.ansible.com%2F" target="_blank">Ansible</a>。</p><p data-omnivore-anchor-idx="33">Ansible 是一个功能强大的运维管理工具，支持几乎所有发行版，它的各种功能可以使用 playbook 文件来控制，其实就是 yaml 格式的文件，学习门槛和可读性都要好上不少。</p><p data-omnivore-anchor-idx="34">Ansible 的设计思路就是同时管理多台远程服务器，远程服务器不需要安装 Ansible，只需在本地电脑安装，并配置好服务器的连接方式，便可以快捷管理远程服务器了，要想管理个人电脑的配置文件，只需将连接方式配置为本地连接即可，可以理解为远程与本地机器都是同一台电脑。</p><h2 data-omnivore-anchor-idx="35" id="ss-hId-2" hid="ss-hId-2">开始之前</h2><p data-omnivore-anchor-idx="36">因为篇幅原因，我在文章中不可能详细讲解 Ansible 的具体用法，如果想要学习 Ansible 的使用方法，我个人比较推荐观看 Youtube 上 Learn Linux TV 做的这个<a data-omnivore-anchor-idx="37" href="https://sspai.com/link?target=https%3A%2F%2Fyoutube.com%2Fplaylist%3Flist%3DPLT98CRl2KxKEUHie1m24-wkyHpEsa4Y70%26si%3DyhSJMj6EYMUemCdP" target="_blank">系列教程</a>，如果想要了解一些高级用法，可以进一步阅读 Ansible 的<a data-omnivore-anchor-idx="38" href="https://sspai.com/link?target=https%3A%2F%2Fdocs.ansible.com%2Fansible%2Flatest%2Findex.html" target="_blank">官方文档</a>，不过我个人觉得 Ansible 官方的文档写的有些杂乱，了解一些简单用法后直接去 Stack Overflow 去搜似乎更加高效一些😆。</p><h2 data-omnivore-anchor-idx="39" id="ss-hId-3" hid="ss-hId-3">模板仓库</h2><p data-omnivore-anchor-idx="40">我的 Ansible 配置文件结构主要参考了<a data-omnivore-anchor-idx="41" data-omnivore-anchor-idx="528">判断条件</h3><p data-omnivore-anchor-idx="529">我们也可以让任务只在指定条件下运行，若条件不满足就跳过任务。在这个实例中，我打算安装 kmonad 软件来修改笔记本键盘的键位，配置文件 <code data-omnivore-anchor-idx="530" class="hljs data-omnivore-anchor-idx="533" class="hljs language-awk language-dts"><span data-omnivore-anchor-idx="534" class="hljs-regexp">/etc/</span>kmonad<span data-omnivore-anchor-idx="535" class="hljs-regexp">/</span></code> 目录下，并启用 <code data-omnivore-anchor-idx="536" class="hljs language-angelscript language-aspectj"><span data-omnivore-anchor-idx="537" data-omnivore-anchor-idx="747">另外需要注意，在 Ansible 中使用变量，变量名称不能用某些特殊符号，比如破折号（-），不然运行时会报错，但是可以使用下划线（_）。</p><h3 data-omnivore-anchor-idx="748">模板</h3><p data-omnivore-anchor-idx="749">变量适用于需要批量修改某个值的情况，可如果需要修改的值是在某个文件里呢，这时候就可以使用模板功能了。还是拿之前安装 kmonad 的例子，kmonad 一次只能处理一个键盘的映射，如果需要配置多个键盘，就要为每个键盘单独编辑一个配置文件，然后启用多个 kmonad 后台服务，借助模板功能，我们就可以使用一个模板来同时为多个键盘设置配置文件。</p><p data-omnivore-anchor-idx="750">kmonad 的配置文件如何编写不在本文的讨论范围内，具体可以查看 kmonad 的项目<a data-omnivore-anchor-idx="751" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fkmonad%2Fkmonad" target="_blank">文档</a>，在这里需要关心的是，在 kmonad 配置文件最开头需要定义 <code data-omnivore-anchor-idx="752" class="hljs language-ebnf language-hsp"><span data-omnivore-anchor-idx="753" class="hljs-attribute">input</span></code> 和 <code data-omnivore-anchor-idx="754" class="hljs language-ebnf language-gauss"><span data-omnivore-anchor-idx="755" class="hljs-attribute">output</span></code>，大概是这样：</p><pre data-omnivore-anchor-idx="756"><code data-omnivore-anchor-idx="757" class="hljs language-clojure language-hy">(<span data-omnivore-anchor-idx="758" class="hljs-name">defcfg</span>
  input  (<span data-omnivore-anchor-idx="759" class="hljs-name">device-file</span> <span data-omnivore-anchor-idx="760" class="hljs-string">"/dev/input/device-file"</span>)
  output (<span data-omnivore-anchor-idx="761" class="hljs-name">uinput-sink</span> <span data-omnivore-anchor-idx="762" class="hljs-string">"output-name"</span>)
  fallthrough <span data-omnivore-anchor-idx="763" class="hljs-literal">true</span>
