data-omnivore-anchor-idx="37">影音服务器</strong>，<strong data-omnivore-anchor-idx="38">服务器访问存储的方式</strong>，<strong data-omnivore-anchor-idx="39">播放客户端</strong>，<strong data-omnivore-anchor-idx="40">网络访问影音服务器</strong>的方式。</p><figure data-omnivore-anchor-idx="41"><img data-omnivore-anchor-idx="42" data-omnivore-anchor-idx="46">例如，你自建的 NAS 服务器里、直接存在本地电脑里、存在某个网盘里。</p><p data-omnivore-anchor-idx="47"><strong data-omnivore-anchor-idx="48">影音服务器</strong>：你使用了什么软件系统作为影音服务器。</p><p data-omnivore-anchor-idx="49">这里你可以选择使用 <a data-omnivore-anchor-idx="50" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a>、<a data-omnivore-anchor-idx="51" href="https://sspai.com/link?target=https%3A%2F%2Femby.media%2F" target="_blank">Emby</a>、<a data-omnivore-anchor-idx="52" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a>、<a data-omnivore-anchor-idx="56" href="https://sspai.com/link?target=https%3A%2F%2Femby.media%2F" target="_blank">Emby</a>、<a data-omnivore-anchor-idx="57" href="https://sspai.com/link?target=https%3A%2F%2Fwww.plex.tv%2F" target="_blank">Plex</a>、<a data-omnivore-anchor-idx="58" href="https://sspai.com/link?target=https%3A%2F%2Fkodi.tv%2F" target="_blank">Kodi</a> 这几个专门的媒体服务器系统软件中，我推荐的是 <a data-omnivore-anchor-idx="59" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a>，我用了它一年多的时间，它是 <a data-omnivore-anchor-idx="60" href="https://sspai.com/link?target=https%3A%2F%2Femby.media%2F" target="_blank">Emby</a> 的开源版本。早期，<a data-omnivore-anchor-idx="61" href="https://sspai.com/link?target=https%3A%2F%2Femby.media%2F" target="_blank">Emby</a> 也是开源的，后面转向了闭源的收费软件，<a data-omnivore-anchor-idx="62" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a> 是原本 <a data-omnivore-anchor-idx="63" href="https://sspai.com/link?target=https%3A%2F%2Femby.media%2F" target="_blank">Emby</a> 开源仓库 fork 下来继续维护的版本。<a data-omnivore-anchor-idx="64" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a> 整体使用下来感觉 UI 比较清爽，符合直觉，对着点一点就能明白如何操作。<a data-omnivore-anchor-idx="65" href="https://sspai.com/link?target=https%3A%2F%2Fwww.plex.tv%2F" target="_blank">Plex</a> 下载过，但是安装完根本打不开，完全部署不起来，它本身也是收费软件，所以也 pass。<a data-omnivore-anchor-idx="66" href="https://sspai.com/link?target=https%3A%2F%2Fkodi.tv%2F" target="_blank">Kodi</a> 是老牌的经典媒体服务器软件，为整个社区生态发展做出了很多贡献，但是用下来感觉像是针对电视等产品形态设计使用的，不过功能看起来很强大，有很多可以配的东西。因此，综合下来，我觉得 <a data-omnivore-anchor-idx="67" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a> 是影音服务器软件不错的一个选择。</p><p data-omnivore-anchor-idx="68">除此以外，你也不一定需要选择一个专门的影音服务器系统软件，来管理视频资源。你可以直接搭建一个自托管的云盘服务，或者已经使用了某个云盘作为资源存储，并且这个云盘提供了某些开放能力供用户访问视频资源。目前，比较流行的方式是暴露 WebDAV 形式的接口，供客户端访问使用；也有某些云盘提供商给了特定的 SDK，供客户端访问使用。然后，使用特定播放客户端（Infuse / VidHub 等），读取服务器上的资源，以此在客户端上实现 <a data-omnivore-anchor-idx="69" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a> 等影音服务器提供的能力。</p><p data-omnivore-anchor-idx="70">具体来说，自托管网盘，只推荐目前比较流行的 <a data-omnivore-anchor-idx="71" href="https://sspai.com/link?target=https%3A%2F%2Falist.nn.ci%2Fzh%2F" target="_blank">AList</a>，它提供了一个比较易用的 Web UI，支持挂载几十种网盘，并且提供了 WebDAV 接口供客户端访问。提供 WebDAV 开放能力的云盘，推荐两个，一个是<a data-omnivore-anchor-idx="72" href="https://sspai.com/link?target=https%3A%2F%2Fwww.aliyundrive.com%2F" target="_blank">阿里云盘</a>，一个是 <a data-omnivore-anchor-idx="73" href="https://sspai.com/link?target=https%3A%2F%2Fmypikpak.com%2Fdrive%2Factivity%2Finvited%3Finvitation-code%3D36743699" target="_blank">PikPak</a>。其中，<a data-omnivore-anchor-idx="74" href="https://sspai.com/link?target=https%3A%2F%2Fwww.aliyundrive.com%2F" target="_blank">阿里云盘</a>的价格大概 18 每月，给 8 TB 空间，不限速，但是目前似乎因为给大家薅了好几年了，疑似有开始噶韭菜的嫌疑，但反正我目前用的没有任何问题；<a data-omnivore-anchor-idx="75" href="https://sspai.com/link?target=https%3A%2F%2Fmypikpak.com%2Fdrive%2Factivity%2Finvited%3Finvitation-code%3D36743699" target="_blank">PikPak</a>，在打折时期大概 200 一年，平常比较贵，疑似是原迅雷的团队出海搞的产品，主要卖点其实是下 torrent + 网盘，同样我用下来没有感觉有任何问题。</p><p data-omnivore-anchor-idx="76"><strong data-omnivore-anchor-idx="77">资源访问</strong>：你的影音服务器如何从资源存储中读取视频，是连接两者的桥梁，往往根据服务器和存储所处的位置，选择对应的访问方式。</p><p data-omnivore-anchor-idx="78">例如，可能有几种组合方式：</p><ul data-omnivore-anchor-idx="79"><li data-omnivore-anchor-idx="80">你有公网的云服务器，视频存在服务器本地，服务器启动 Jellyfin：于是 Jellyfin 就是简单的通过读取本地目录，实现资源访问。</li><li data-omnivore-anchor-idx="81">你有公网的云服务器，视频存在某个云盘中，服务器启动 Jellyfin：由于Jellyfin 只支持读取本地目录，因此你需要将这个云盘，通过 AList / rclone 等软件，将网络目录挂载成「真实」的本地目录（下文介绍）。</li><li data-omnivore-anchor-idx="82">你的视频存在本地电脑，在本地启动 Jellyfin：同上，Jellyfin 读取本地目录。</li><li data-omnivore-anchor-idx="83">你的视频存在某个网盘中，在本地启动 Jellyfin：同上，你需要将网盘挂载到本地，在 Windows 中，你可以使用 Windows 原生的 WebDAV 功能、rclone、Rai Drive 来实现本地目录的挂载。</li><li data-omnivore-anchor-idx="84">你的视频存在 NAS 里，在公网的云服务器上启动 Jellyfin：那么你可能需要先本地起一个 WebDAV 或者其它什么服务器，内网穿透到公网或者你直接有公网 IP，然后在把暴露在公网的 WebDAV 挂载的云服务器本地，供 Jellyfin 使用。</li><li data-omnivore-anchor-idx="85">你的视频存在阿里云盘里，你直接通过阿里云盘的开放能力连接播放器使用：那么资源访问由阿里云内部掌控，与我们无关。</li><li data-omnivore-anchor-idx="86">……</li></ul><p data-omnivore-anchor-idx="87">你可以发现，根据你的视频存储位置不同、运行影音服务器和播放器客户端不同，资源访问方式也是千奇百怪，在实现上都是理论可行的。但是，我们需要强调的是，整个从用户到访问视频资源的完整链路，拖得越长，例如你要把 NAS 中的视频给公网云服务器使用，就经过 3 层软件，因此，整个访问的稳定性、速度等体验都可能会打折扣。正如短板效应，中间任何一个环节有差错，整个观看链路就有问题。对于长链路的部署方案，你可能需要实际尝试，慎重选择，但是本着折腾着玩的精神，后文其实也演示了这样的一种方案。</p><p data-omnivore-anchor-idx="88"><strong data-omnivore-anchor-idx="89">网络访问</strong>：你的播放客户端如何访问到你的影音服务器。</p><p data-omnivore-anchor-idx="90">如果你只在内网使用，即只在自己家里用，那么你几乎不需要考虑这个问题，你只需要保证服务器和你的电脑、手机等客户端，在同一个 Wi-Fi 下就行了（或者服务器在公网）。</p><p data-omnivore-anchor-idx="91">如果你需要公网访问，有 2 种可能：</p><ul data-omnivore-anchor-idx="92"><li data-omnivore-anchor-idx="93">你的影音服务器跑在你的 NAS 上：那么你需要有一个公网 IP 或者使用内网穿透，来将影音服务器暴露在公网。这个方案可能需要注意的是，你的网络上传带宽怎么样，内网穿透需要有云服务器或者购买内网穿透服务或者薅 Cloudflare 的羊毛，这些会无形中增加你的部署成本。</li><li data-omnivore-anchor-idx="94">你的影音服务器跑在云服务上：那么其本身就是在公网上的，有 IP 或者域名就能公网访问。</li></ul><p data-omnivore-anchor-idx="95"><strong data-omnivore-anchor-idx="96">播放客户端</strong>：你如何点播影音服务器上的视频。</p><p data-omnivore-anchor-idx="97">如果你使用 <a data-omnivore-anchor-idx="98" href="https://sspai.com/link?target=https%3A%2F%2Fjellyfin.org%2F" target="_blank">Jellyfin</a> 等某种影音服务器软件，一般它们都会提供 Web UI 或者相应的应用，来访问服务器上视频。</p><p data-omnivore-anchor-idx="99">如果你在影音服务器部署时，没有使用的专门的软件，而是采用暴露 WebDAV 接口等形式，那么你就需要挑选一款合适的播放客户端：</p><ul data-omnivore-anchor-idx="100"><li data-omnivore-anchor-idx="101">对于苹果用户，目前最流行的是 <a data-omnivore-anchor-idx="102" href="https://sspai.com/link?target=https%3A%2F%2Ffirecore.cn%2Finfuse" target="_blank">Infuse</a>，以及国人开发的 <a data-omnivore-anchor-idx="103" href="https://sspai.com/link?target=https%3A%2F%2Fzh.vidhub.okaapps.com%2F" target="_blank">VidHub</a> 正在追赶 <a data-omnivore-anchor-idx="104" href="https://sspai.com/link?target=https%3A%2F%2Ffirecore.cn%2Finfuse" target="_blank">Infuse</a>，也达到了相当高的完成度。</li><li data-omnivore-anchor-idx="105">由于我不是安卓用户，也没有安卓设备，没有实际使用过，只列举一个 Infuse 的可能替代品，<a data-omnivore-anchor-idx="106" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2FAttemptD%2FAfuseKt-release" target="_blank">AfuseKt</a>；另外，由网易开发的 Fimly，还处于非常早期的状态，不知道有没有安卓的版本。</li><li data-omnivore-anchor-idx="107">PC 端还有一个方案是使用<a data-omnivore-anchor-idx="108" href="https://sspai.com/link?target=https%3A%2F%2Fwww.dandanplay.com%2F" target="_blank">弹弹 data-omnivore-anchor-idx="121">前 3 种主要因素几乎可以任意排列组合，形成多种不一样的方案，各个方案各有自己满足的需求和优劣，可能需要你自己根据需求抉择。</p><p data-omnivore-anchor-idx="122">下面列举了我使用过的几套无需 NAS 的影音服务器方案。<strong data-omnivore-anchor-idx="134">缺点：整个视频播放链路比较长，相应的配置比较麻烦，可能会出现速度、稳定性不太行的情况。</li></ul></li><li data-omnivore-anchor-idx="135">数据存在网盘里，公网服务器部署 AList，不用影音服务器软件，使用 Infuse / VidHub / 支持访问 WebDAV 的播放器：<ul data-omnivore-anchor-idx="136"><li data-omnivore-anchor-idx="137">成本：网盘会员，公网服务器等云服务；</li><li data-omnivore-anchor-idx="138">优点：AList 支持挂载非常多种网盘；</li><li data-omnivore-anchor-idx="139">缺点：Infuse / 如果需要公网访问，可能会比较麻烦（没有实际用过，感觉），诸如配置内网穿透等等，考虑自家的网络情况等等。</li><li data-omnivore-anchor-idx="152">各类无需 NAS 或者需要 NAS 的方案，有操作麻烦的，需要具备一定计算机知识和实操能力，也有简单无脑的。比如，直接用阿里云盘 + Infuse / VidHub 弄起来起来非常简单，而涉及服务器就比较麻烦。对于 开始简单尝试影音服务器的朋友。</p><h3 data-omnivore-anchor-idx="245">云服务器部署 AList</h3><p data-omnivore-anchor-idx="246">对应方案 3，它的部署结构如下图所示：</p><figure data-omnivore-anchor-idx="247"><img
