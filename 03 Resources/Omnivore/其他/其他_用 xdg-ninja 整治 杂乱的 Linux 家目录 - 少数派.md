data-omnivore-anchor-idx="14"><h2 data-omnivore-anchor-idx="15" id="ss-hId-1" hid="ss-hId-1">前言</h2><p data-omnivore-anchor-idx="16">Linux 系统下，大多数软件的配置文件与数据文件都会以隐藏文件的形式存放在用户的家目录之下，并且隐藏文件的文件名都是以英文句号开头的，也就是一个点，所以很多人将这些文件称之为 dotfiles。</p><p data-omnivore-anchor-idx="17">在现代化的 Linux 发行版中，理想情况下软件对于 dotfiles 的存放会遵循 <a data-omnivore-anchor-idx="18" href="https://sspai.com/link?target=https%3A%2F%2Fwiki.archlinux.org%2Ftitle%2FXDG_Base_Directory" target="_blank">XDG 标准</a>，也就是说，软件的配置文件、数据文件、缓存文件等等，会分别存放到 <code data-omnivore-anchor-idx="19" class="hljs language-undefined">XDG_CONFIG_HOME</code>、<code data-omnivore-anchor-idx="20" class="hljs language-autohotkey">XDG_DAT<span data-omnivore-anchor-idx="21" class="hljs-built_in">A_HOME</span></code> 以及 <code data-omnivore-anchor-idx="22" class="hljs language-undefined">XDG_STATE_HOME</code> 等目录中，在默认情况下，这些目录分别对应为 <code data-omnivore-anchor-idx="23" class="hljs language-arcade language-arduino">~<span data-omnivore-anchor-idx="24" class="hljs-regexp">/.config/</span></code>、<code data-omnivore-anchor-idx="25" class="hljs language-pgsql language-applescript">~/.<span data-omnivore-anchor-idx="26" class="hljs-keyword">local</span>/<span data-omnivore-anchor-idx="27" class="hljs-keyword">share</span>/</code> 和 <code data-omnivore-anchor-idx="28" class="hljs language-arcade language-awk">~<span data-omnivore-anchor-idx="29" class="hljs-regexp">/.cache/</span></code>。</p><p data-omnivore-anchor-idx="30">但现实情况远没有那么完美，很多软件会将配置文件或数据文件简单粗暴地放在用户的家目录根文件夹里面，导致家目录充满了杂乱无章的文件或文件夹。造成这种情况的原因也很复杂，可能是系统某些环境变量配置有误，又或者是某些软件的历史遗留问题，也可能只是单纯的软件并没有遵循 XDG 规范来进行设计。</p><p data-omnivore-anchor-idx="31">对于这种情况，其实也大可以眼不见为净，在文件管理器中关掉显示隐藏文件的选项，大部分时候倒也看不到。不过其中有不少软件是可以通过一些配置让它们的文件放到该去的地方，若你是强迫症就是看这些文件不爽，也不是没有办法。</p><p data-omnivore-anchor-idx="32">但是一个个去查找相关软件的配置多少还是有些麻烦了。有没有什么更好的办法来整治这些「违章建筑」呢？答案是肯定的，<a data-omnivore-anchor-idx="33" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fb3nj5m1n%2Fxdg-ninja" target="_blank">xdg-ninja</a> 这个项目就是专门用来检查家目录中不合规的文件与文件夹的。</p><h2 data-omnivore-anchor-idx="34" id="ss-hId-2" hid="ss-hId-2">开始安装</h2><p data-omnivore-anchor-idx="35">xdg-ninja 存在于一部分包管理器的软件仓库中，比如 Nix、AUR 和 Homebrew，软件依赖 jq 和 find 这两个命令行工具，也可以选择安装 glow 来让命令行输出更有可读性。如果 xdg-ninja 没有在你使用的发行版仓库中，因为其本身只是个 bash 脚本，你也可以在安装好相关依赖后直接克隆 GitHub 仓库，然后运行其中的 <code data-omnivore-anchor-idx="36" class="hljs language-css language-stata"><span data-omnivore-anchor-idx="37" class="hljs-selector-tag">xdg-ninja</span><span data-omnivore-anchor-idx="38" class="hljs-selector-class">.sh</span></code> 脚本。</p><p data-omnivore-anchor-idx="39">在终端中运行 xdg-ninja，就可以看到当前用户家目录中有哪些文件是可以移动的，以及需要做什么配置，这其中可以移动的文件类型与建议配置都是来自于各个软件的相关文档与用户贡献，如果你发现有文件没有检测到，也可以给项目提交规则。</p><figure data-omnivore-anchor-idx="40"><img data-omnivore-anchor-idx="41" data-omnivore-original-src="https://cdnfile.sspai.com/2024/07/17/2671f36d0e1497e19af8c006477bba94.png?imageView2/2/format/webp" src="https://proxy-prod.omnivore-image-cache.app/0x0,s8YXjKM4bOWRJjgRd32FBAV8fay5xanMpdDQdb3q3ZDs/https://cdnfile.sspai.com/2024/07/17/2671f36d0e1497e19af8c006477bba94.png?imageView2/2/format/webp" data-original="https://cdnfile.sspai.com/2024/07/17/2671f36d0e1497e19af8c006477bba94.png?imageView2/2/format/webp" data-index="0"></figure><p data-omnivore-anchor-idx="42">xdg-ninja 并不会自动为你移动家目录中的文件，事实上，它不会修改任何文件，所以不用担心它会搞乱你的家目录。它所做的，就只有读取家目录中的文件名，与仓库中的规则比对，从而显示出哪些文件是可以移动的，之后移动文件与进行配置都需要手动进行。</p><p data-omnivore-anchor-idx="43">有点反直觉的是，xdg-ninja 的输出内容中，红色的项目代表的是可以移动的文件，而黄色的项目代表的是不可以移动，或是虽然可以移动，但之后还仍有可能被重新创建的文件。</p><h2 data-omnivore-anchor-idx="44" id="ss-hId-3" hid="ss-hId-3">设置环境变量</h2><p data-omnivore-anchor-idx="45">xdg-ninja data-original="https://cdnfile.sspai.com/2024/07/17/271bbd9151bbbb62fbee84e550a4667e.png?imageView2/2/format/webp" data-index="1"></figure><p data-omnivore-anchor-idx="54"><a
