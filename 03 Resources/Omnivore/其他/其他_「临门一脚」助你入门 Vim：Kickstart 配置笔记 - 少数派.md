data-omnivore-anchor-idx="15"><h2 data-omnivore-anchor-idx="16" id="ss-hId-1" hid="ss-hId-1">前言</h2><p data-omnivore-anchor-idx="17">Vim 绝对是一个让很多人又爱又恨的软件，爱它的速度快与功能强大，恨它的学习曲线与复杂的配置。我接触 Vim 的这些年来，从原版 Vim 折腾到 Neovim，也慢慢构建了一套属于自己的 Neovim 配置，主题、快捷键、插件配置等等都比较顺手了，也逐渐习惯用 Neovim 编辑一切，事实上，我在此网站发布的文章，包括目前正在写的这篇，都是我用 Neovim 以 Markdown 格式编辑完成的。但是随着时间的流逝，我也遇到一些问题，主要的问题是我的配置大多都是东拼西凑从互联网各处抄来的，配置文件写得比较杂乱且没有很好地作注释，时间一长搞得我自己也看不懂我的配置文件了，遇到一些问题要排查就要废挺多脑筋。</p><p data-omnivore-anchor-idx="18">网上也存在一些现成的 Neovim 配置，或者叫「Neovim 发行版」，比如 <a data-omnivore-anchor-idx="19" href="https://sspai.com/link?target=https%3A%2F%2Fwww.lazyvim.org%2F" target="_blank">LazyVim</a>、<a data-omnivore-anchor-idx="20" href="https://sspai.com/link?target=https%3A%2F%2Fwww.lunarvim.org%2F" target="_blank">LunarVim</a> 和 <a data-omnivore-anchor-idx="21" href="https://sspai.com/link?target=https%3A%2F%2Fnvchad.com%2F" target="_blank">NvChad</a> 等等，这些所谓的发行版都提供了开即用的使用体验，不过我个人倒是觉得这些发行版有些「重」了，根据我自己的使用情况，可能根本用不到里面的很多高级功能，而且后期自定义与添加插件也多少有点不方便。</p><p data-omnivore-anchor-idx="22">就在最近，我了解到了一个项目 <a data-omnivore-anchor-idx="23" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fnvim-lua%2Fkickstart.nvim" target="_blank">kickstart.nvim</a>，按照项目的介绍，这并不是一个 Neovim 发行版，而是一套 Neovim 配置的「出发点」，追求用最少的配置达到可以开箱即用的功能，同时对配置内容做了很详尽的注释，用户可以在这一套配置之上进一步自定义，打造属于自己的 Neovim 配置。</p><p data-omnivore-anchor-idx="24">在详细看了一遍项目的内容后，发现我常用的绝大多数功能，在这个项目中都已经配置好了，而且没有太多多余的功能。所以我打算，在这个项目的基础上，重新自定义一套我自己的配置，并对配置内容做好整理与注释，方便未来的自己进一步管理。</p><h2 data-omnivore-anchor-idx="25" id="ss-hId-2" hid="ss-hId-2">开始安装</h2><h3 data-omnivore-anchor-idx="26">前置要求</h3><p data-omnivore-anchor-idx="27">首先，<s data-omnivore-anchor-idx="28">要学会</s><a data-omnivore-anchor-idx="29" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fhakluke%2Fhow-to-exit-vim" target="_blank"><s data-omnivore-anchor-idx="30">如何退出 Vim</s></a>，也就是说了解一些 Vim 的基础操作，比如一些基础的移动、编辑、保存与退出之类的。</p><p data-omnivore-anchor-idx="31">之后，要了解一些 Lua 的基本用法，因为这个项目的配置文件是用 Lua 编写的，不了解也没关系，我就是在自己折腾过程中慢慢了解 Lua 的语法的。</p><p data-omnivore-anchor-idx="32">接着，需要安装最新稳定版或 nightly 版本的 Neovim，旧版本的 Neovim 可能有些特性不兼容，原版的 Vim 也不行，因为不支持 lua 配置文件。</p><p data-omnivore-anchor-idx="33">最后，安装项目推荐的 <a data-omnivore-anchor-idx="34" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fnvim-lua%2Fkickstart.nvim%3Ftab%3Dreadme-ov-file%23install-external-dependencies" target="_blank">外部依赖</a>，如 git、make、unzip、gcc 等等，以及可选安装 Nerd Font 字体用来在终端显示图标。</p><h3 data-omnivore-anchor-idx="35">安装</h3><p data-omnivore-anchor-idx="36">如果你已经有一套 Neovim 配置了，需要将位于 <code data-omnivore-anchor-idx="37" class="hljs language-arcade language-arduino">~<span data-omnivore-anchor-idx="38" class="hljs-regexp">/.config/</span>nvim/</code> 的配置文件备份到别处，并将配置文件目录 <code data-omnivore-anchor-idx="39" class="hljs language-arcade language-arduino">~<span data-omnivore-anchor-idx="40" class="hljs-regexp">/.config/</span>nvim/</code> 与数据目录 <code data-omnivore-anchor-idx="41" class="hljs language-awk language-crystal">~<span data-omnivore-anchor-idx="42" class="hljs-regexp">/.local/</span>share<span data-omnivore-anchor-idx="43" class="hljs-regexp">/nvim/</span></code> 删除。</p><p data-omnivore-anchor-idx="44">或者也可以让新旧配置文件共存，添加环境变量 <code data-omnivore-anchor-idx="45" class="hljs language-undefined">NVIM_APPNAME</code> 并运行 nvim，比如 <code data-omnivore-anchor-idx="46" class="hljs language-ini language-makefile"><span data-omnivore-anchor-idx="47" class="hljs-attr">NVIM_APPNAME</span>=<span data-omnivore-anchor-idx="48" class="hljs-string">"nvim-kickstart"</span> nvim</code> 就可以让 Neovim 以 <code data-omnivore-anchor-idx="49" class="hljs language-arcade language-arduino">~<span data-omnivore-anchor-idx="50" class="hljs-regexp">/.config/</span>nvim-kickstart</code> 作为配置文件目录启动，数据目录也会相应的变为 <code data-omnivore-anchor-idx="51" class="hljs language-awk language-crystal">~<span data-omnivore-anchor-idx="52" class="hljs-regexp">/.local/</span>share<span data-omnivore-anchor-idx="53" class="hljs-regexp">/nvim-kickstart/</span></code>，我个人是在 <code data-omnivore-anchor-idx="54" class="hljs language-asciidoc language-css"><span data-omnivore-anchor-idx="55" class="hljs-title">.zshrc</span></code> 中添加了一行 alias：</p><pre data-omnivore-anchor-idx="56"><code data-omnivore-anchor-idx="57" class="hljs language-sml language-vhdl">alias k=<span data-omnivore-anchor-idx="58" class="hljs-symbol">'NVIM_APPNAME</span>=<span data-omnivore-anchor-idx="59" class="hljs-string">"nvim-kickstart"</span> nvim'</code></pre><p data-omnivore-anchor-idx="60">这样就可以用命令 <code data-omnivore-anchor-idx="61" class="hljs language-ebnf"><span data-omnivore-anchor-idx="62" class="hljs-attribute">k</span></code> 来启动新的 Neovim 配置文件，而常规的 <code data-omnivore-anchor-idx="63" class="hljs language-ebnf"><span data-omnivore-anchor-idx="64" class="hljs-attribute">nvim</span></code> 命令则是启动旧的配置文件。</p><p data-omnivore-anchor-idx="65">之后将 kickstart 项目克隆到本地，我个人并没有用原版的 kickstart，而是用的它的一个 Fork，<a data-omnivore-anchor-idx="66" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fdam9000%2Fkickstart-modular.nvim" target="_blank">kickstart-modular</a>，相比于原版的 kickstart，这个项目将配置文件拆成了多份，在管理上更方便一些，实际内容是一样的。</p><pre data-omnivore-anchor-idx="67"><code data-omnivore-anchor-idx="68" class="hljs language-crmsh language-nginx">git <span data-omnivore-anchor-idx="69" class="hljs-keyword">clone</span> <span data-omnivore-anchor-idx="70" class="hljs-title">https</span>://github.com/dam9000/kickstart-modular.nvim.git <span data-omnivore-anchor-idx="71" class="hljs-string">"${XDG_CONFIG_HOME:-$HOME/.config}"</span>/nvim</code></pre><p data-omnivore-anchor-idx="72">当然如果选择了新旧配置文件共存，需要相应修改路径：</p><pre data-omnivore-anchor-idx="73"><code data-omnivore-anchor-idx="74" class="hljs language-crmsh language-nginx">git <span data-omnivore-anchor-idx="75" class="hljs-keyword">clone</span> <span data-omnivore-anchor-idx="76" class="hljs-title">https</span>://github.com/dam9000/kickstart-modular.nvim.git <span data-omnivore-anchor-idx="77" class="hljs-string">"${XDG_CONFIG_HOME:-$HOME/.config}"</span>/nvim-kickstart</code></pre><p data-omnivore-anchor-idx="78">另外文档中也比较推荐自己将仓库 Fork 下来，并克隆自己的 Fork 仓库，这样在后期比较方便版本管理与维护。</p><p data-omnivore-anchor-idx="79">之后重新打开 Neovim，插件管理器 Lazy 会自动下载安装插件，之后呈现在你面前的就是一个完全配置好开箱即用的 Neovim 配置了。</p><figure data-omnivore-anchor-idx="80"><img data-omnivore-anchor-idx="81" data-omnivore-original-src="https://cdnfile.sspai.com/2024/07/03/d40ed15b51eb8618060148ac278a568c.png?imageView2/2/format/webp" data-original="https://cdnfile.sspai.com/2024/07/03/d40ed15b51eb8618060148ac278a568c.png?imageView2/2/format/webp" data-index="0"></figure><p data-omnivore-anchor-idx="82">之后你就可以探索这套配置可以用来做什么了。它用了 <a data-omnivore-anchor-idx="83" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Ffolke%2Fwhich-key.nvim" target="_blank">Which Key</a> 插件用来管理快捷键，只要按下 leader data-omnivore-original-src="https://cdnfile.sspai.com/2024/07/03/db0fd3424bd3cddac39e8ed4c45f9996.png?imageView2/2/format/webp" data-omnivore-anchor-idx="87">也可以仔细阅读配置文件中的注释内容，并了解其中每个插件的作用；或者也可以观看作者录制的<a data-omnivore-anchor-idx="88" href="https://sspai.com/link?target=https%3A%2F%2Fyoutu.be%2Fm8C0Cq9Uv9o" target="_blank">介绍视频</a>，以对这个项目有更直观的了解。</p><h2 data-omnivore-anchor-idx="89" id="ss-hId-3" hid="ss-hId-3">自定义配置</h2><p data-omnivore-anchor-idx="90">在了解了这个项目的大致内容后，就需要根据自己的需要对配置进行自定义修改了，在这一节内容中我会 kickstart 的配置进行修改，以满足我自己的使用习惯。</p><h3 data-omnivore-anchor-idx="91">内置选项</h3><p data-omnivore-anchor-idx="92">kickstart 在配置文件中有些选项是默认禁用的没有启用，我们可以根据自己的喜好将其启用，也可以禁用其中一些选项。</p><p data-omnivore-anchor-idx="93">首先编辑 <code data-omnivore-anchor-idx="94" class="hljs language-css language-kotlin"><span data-omnivore-anchor-idx="95" class="hljs-selector-tag">init</span><span data-omnivore-anchor-idx="96" class="hljs-selector-class">.lua</span></code> 文件，找到 <code data-omnivore-anchor-idx="97" class="hljs language-ini language-nix"><span data-omnivore-anchor-idx="98" class="hljs-attr">vim.g.have_nerd_font</span> = <span data-omnivore-anchor-idx="99" class="hljs-literal">false</span></code>，这个选项默认禁用了 Nerd Font 图标字体，使用 Unicode emoji 作为图标字体，如果你的终端已经配置好了 Nerd Font 的话，可以将这个选项改为 true，这样界面中的图标就会以 Nerd Font 图标字体显示了。</p><figure data-omnivore-anchor-idx="100"><img data-omnivore-anchor-idx="101" data-omnivore-original-src="https://cdnfile.sspai.com/2024/07/03/7a97d66e08c7733535649c2228a21ba7.png?imageView2/2/format/webp" src="https://proxy-prod.omnivore-image-cache.app/0x0,sD9Ae2mrpTk3IHuqGcYpT6b6QjiFz8snWfBMryO_dnUU/https://cdnfile.sspai.com/2024/07/03/7a97d66e08c7733535649c2228a21ba7.png?imageView2/2/format/webp" data-original="https://cdnfile.sspai.com/2024/07/03/7a97d66e08c7733535649c2228a21ba7.png?imageView2/2/format/webp" data-index="2"></figure><p data-omnivore-anchor-idx="102">之后编辑 <code data-omnivore-anchor-idx="103" class="hljs language-vim language-gams"><span data-omnivore-anchor-idx="104" class="hljs-keyword">lua</span>/<span data-omnivore-anchor-idx="105" class="hljs-keyword">options</span>.<span data-omnivore-anchor-idx="106" class="hljs-keyword">lua</span></code> 文件。首先找到 <code data-omnivore-anchor-idx="107" class="hljs language-ini language-nix"><span data-omnivore-anchor-idx="108" class="hljs-attr">vim.opt.relativenumber</span> = <span data-omnivore-anchor-idx="109" class="hljs-literal">true</span></code>，这个选项控制显示相对于当前光标所在行的相对行号，打开这个选项后就可以比较方便地跳转多行。这一行是被注释掉的，删掉前面的 <code data-omnivore-anchor-idx="110" class="hljs language-ada language-applescript"><span data-omnivore-anchor-idx="111" class="hljs-comment">--</span></code> 就可以取消注释，另外因为安装了 <a data-omnivore-anchor-idx="112" href="https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2FnumToStr%2FComment.nvim" target="_blank">Comment.nvim</a> 插件，可以直接在 Visual 模式中选中这一行，按快捷键 <code data-omnivore-anchor-idx="113" class="hljs language-ebnf language-llvm"><span data-omnivore-anchor-idx="114" class="hljs-attribute">gc</span></code> 来快速取消注释。</p><p data-omnivore-anchor-idx="115">接着找到 <code data-omnivore-anchor-idx="116" class="hljs language-ini language-stylus"><span data-omnivore-anchor-idx="117" class="hljs-attr">vim.opt.clipboard</span> = <span data-omnivore-anchor-idx="118" class="hljs-string">'unnamedplus'</span></code>，这个选项可以让 Neovim 与系统共享剪贴板，不过我个人倒不太喜欢这个功能，因为 Vim 每一次剪切或删除操作都会把内容保存进剪贴板，如果与系统共享剪贴板，会导致系统剪贴板被一大堆无意义的内容占据，之后我会定义一个快捷键，专门用来将内容复制到系统剪贴板。同样选中这一行按 <code data-omnivore-anchor-idx="119" class="hljs language-ebnf language-llvm"><span data-omnivore-anchor-idx="120" class="hljs-attribute">gc</span></code> 就可以将内容注释掉。</p><p data-omnivore-anchor-idx="121">然后找到 <code data-omnivore-anchor-idx="122" class="hljs language-ini language-vim"><span data-omnivore-anchor-idx="123" class="hljs-attr">vim.opt.undofile</span> = <span data-omnivore-anchor-idx="124" class="hljs-literal">true</span></code>，这个选项会将文件的修改历史保存到磁盘里，这样即使退出重新打开文件也可以找到之前的修改历史，不过我个人不太喜欢这个功能，所以将其注释掉了，如果觉得这个功能有用也可以保留。</p><h3 data-omnivore-anchor-idx="125">快捷键</h3><p data-omnivore-anchor-idx="126">我个人主要添加了两组快捷键，一个是快速切换与关闭 buffer，另一个是将当前选中内容复制进系统剪贴板，编辑 <code data-omnivore-anchor-idx="127" class="hljs language-vim"><span data-omnivore-anchor-idx="128" class="hljs-keyword">lua</span>/keymaps.<span data-omnivore-anchor-idx="129" class="hljs-keyword">lua</span></code>，在最后插入下面几行：</p><pre data-omnivore-anchor-idx="130"><code data-omnivore-anchor-idx="131" class="hljs language-vim language-pgsql">-- Changeing <span data-omnivore-anchor-idx="132" class="hljs-keyword">buffer</span>

data-omnivore-anchor-idx="813">懒加载更多插件</h3><p data-omnivore-anchor-idx="814">kickstart 使用 Lazy.nvim 来管理插件，从其名字也可以推测出来，这个插件管理器一大特色功能就是懒加载，Lazy 对插件懒加载的配置可谓十分灵活，可以配置让插件在不同的情况下懒加载。让插件只在必须的时候进行加载，可以很大程度上提升 Neovim 的启动速度。</p><p data-omnivore-anchor-idx="815">kickstart 默认已经为一些插件配置了懒加载，还有些插件我前文的配置过程中也按照我自己的使用情况配置了懒加载，不过还有一些插件默认没有配置懒加载，虽然其中大部分插件对启动速度影响并不大，但积少成多还是能省出一点启动时间的。</p><p data-omnivore-anchor-idx="816">首先是 vim-sleuth 和 Comment.nvim，这两个插件大概是作为演示作用，没有配置懒加载，也没有放进单独的配置文件，而是直接写在 <code data-omnivore-anchor-idx="817" class="hljs language-vim language-coq"><span data-omnivore-anchor-idx="818" class="hljs-keyword">lua</span>/lazy-plugins.<span data-omnivore-anchor-idx="819" class="hljs-keyword">lua</span></code> 里面。</p><p data-omnivore-anchor-idx="822" class="hljs-symbol">'tpope</span>/vim-sleuth',</code> 这一行，改成：</p><pre data-omnivore-anchor-idx="823"><code data-omnivore-anchor-idx="824" class="hljs language-ada   },</code></pre><p data-omnivore-anchor-idx="829">Comment.nvim 插件可以快捷地对文档进行注释，这个功能在前文已经介绍过了，我自己实际上也只用到了它的 <code data-omnivore-anchor-idx="830" class="hljs language-ebnf language-llvm"><span data-omnivore-anchor-idx="831" class="hljs-attribute">gc</span></code> 快捷键，所以我打算让它只在按下这个快捷键的时候再启用，找到 <code data-omnivore-anchor-idx="832" class="hljs language-reasonml language-sml">{ 'numToStr/<span data-omnivore-anchor-idx="833" class="hljs-module-access"><span data-omnivore-anchor-idx="834" class="hljs-module"><span data-omnivore-anchor-idx="835" class="hljs-identifier">Comment</span>.</span></span>nvim', opts = {} },</code> 一行，改成：</p><pre data-omnivore-anchor-idx="836"><code data-omnivore-anchor-idx="837" class="hljs language-perl language-sml">  {
