data-omnivore-anchor-idx="17">我有个坚持，不想浪费宝贵时间在低价值信息上，所以会时常反思自己的信息来源。我感兴趣的领域，通常都能找到相应信息渠道，长期关注。但不能只盯着这些领域，也需要一扇小窗口，来偶尔了解其他领域的大事，防止画地为牢。</p><p data-omnivore-anchor-idx="18">以往，我都是利用早晨送老婆孩子的时间，听听新闻电台，了解当天时事。这里面的信息也可以分为两类：</p><ol data-omnivore-anchor-idx="19"><li data-omnivore-anchor-idx="20">肯定对我无价值。如体育新闻、娱乐新闻，我一点也不关心体育和八卦；又如军事新闻，军事信息披露少、难查证，各方报喜不报忧，单从新闻报道获得结论，完全不可靠。</li><li data-omnivore-anchor-idx="21">可能有价值，听了才知道。如社会新闻，近期消费趋势、科技发展导致的新社会现象等，有时能从中得到一些数据和洞察。当然，也有许多毫无价值，比如某豪车肇事逃逸这种，社会构成形形色色，单个个体的行为往往不值得关心。</li></ol><p data-omnivore-anchor-idx="22">近期巴黎奥运会，我的新闻时光几乎被奥运新闻淹没了。导致我开车时不时要瞄一眼大屏上的新闻标题，判断是不是该切下一条。有时候要连切七八条，才能轮到一则我愿意听的。这样既不安全，又让人火大。</p><p data-omnivore-anchor-idx="23">我试过许多可以听新闻的手机 app。如果听头条频道，免不了混进这些不感兴趣的信息。如果订阅几个特定频道，又总会混入上千字的深度报道，敢情我一路就听你一条呢？更新频率的差异也是个问题，订阅的几个频道中，只要有一两个更新量极大，其他频道就相当于不存在了。</p><p data-omnivore-anchor-idx="24">我就想，既然只瞄一眼标题就能判断要不要听，这事儿 AI 难道不能做吗？我可以继续听头条频道，只是让 AI 帮我滤掉一道，可不可行？</p><p data-omnivore-anchor-idx="25">这个想法一冒出来，就完全停不下来了。</p><h2 data-omnivore-anchor-idx="26" id="ss-hId-2" hid="ss-hId-2">实现思路</h2><p data-omnivore-anchor-idx="27">仔细一想就发现，这事压根儿没什么技术含量。但就是找不到一款现成产品，可能是需求过于小众，那我就自己干吧！</p><p data-omnivore-anchor-idx="28">首先，我要在哪实施我的构想？在电脑上写个程序当然可以，但既然听新闻绕不开手机，干脆整个流程都在手机上完成吧，摆脱对其他设备的依赖，否则我出去度个长假还听不了新闻了？所幸我长期使用 Tasker，安卓手机上的一款编程软件，我知道它能实现我想要的效果。</p><p data-omnivore-anchor-idx="29">整个过程不复杂，就这么几步：</p><ol data-omnivore-anchor-idx="30"><li data-omnivore-anchor-idx="31">从新闻源获取当日的头条新闻</li><li data-omnivore-anchor-idx="32">把新闻标题交给 AI，让它判断属于哪类新闻</li><li data-omnivore-anchor-idx="33">过滤掉我不要的几类新闻，剩余新闻以文字形式保存下来</li><li data-omnivore-anchor-idx="34">通过语音合成转成音频新闻，存到特定位置</li><li data-omnivore-anchor-idx="35">以上动作做成自动任务，每天深夜执行一遍</li><li data-omnivore-anchor-idx="36">在音乐播放器创建一个专门的歌单，读取音频新闻</li><li data-omnivore-anchor-idx="37">做另一个自动任务，手机连上车载蓝牙启动播放器，播放新闻</li><li data-omnivore-anchor-idx="38">再做个自动任务，每天把新闻清空，为下一轮做准备</li></ol><h2 data-omnivore-anchor-idx="39" id="ss-hId-3" hid="ss-hId-3">准备轮子</h2><p data-omnivore-anchor-idx="40">以上步骤听起来像个大工程。但好在我不用自己发明轮子，其中许多能力都有现成的工具，把它们整合进来即可。现在，我得把可能用到的基础能力做成一个个小模块，也就是子任务，提前准备好，便于后续组装。</p><p data-omnivore-anchor-idx="41">Tasker 是这些子任务的载体。它是一个手机上的自动化工具，把硬件控制、数学运算、文件操作、网络请求、判断/循环等能力都打散成原子级别，让你自由组合，构建各种各样的自动化工作流。折腾过 iPhone 快捷指令的朋友应该熟悉这套玩法，只是 Tasker 远比快捷指令强大得多。把它归为自动化工具是低估了它，它实际上是个编程软件。</p><p data-omnivore-anchor-idx="42">最基础的用法是根据条件来控制手机硬件，比如连上公司 WiFi 自动静音、连上车载蓝牙启动音乐播放器，这类效果做起来轻轻松松。高级一些的用法，涉及文件操作、网络请求，则需要有编程的思维，但并不需要真的写代码。</p><h3 data-omnivore-anchor-idx="43">网络获取内容</h3><p HTTP 请求，我没做任何额外处理，只把从新闻源获得的信息原封不动传递给外层任务。为什么要包这么一层，而不是直接用呢？这和子任务的执行优先级有关系，后面组装轮子的时候我会再讲。</p><h3 data-omnivore-anchor-idx="52">解析 XML</h3><p data-omnivore-anchor-idx="53">从 RSS 新闻源获得的不是直接能读的新闻，而是一堆 XML 代码的格式。这里需要一点前端知识，因为网页里有时候会遇到代码被写成转义字符的情况，比如左尖括号<code data-omnivore-anchor-idx="58" class="hljs language-undefined">&lt;</code>被写成<code data-omnivore-anchor-idx="59" class="hljs language-1c description 却有不同理解。有的新闻源把全文都写在了 description 里，有的只在这写了摘要，正文藏在详情页里。</p><p data-omnivore-anchor-idx="85">这个子任务就是为了干这个。给它一个页面的完整 HTML 代码，再告诉它要提取哪个标签的内容，它就能取出来，把不相干的菜单、评论、广告、页头页尾全撇掉。</p><p data-omnivore-anchor-idx="126">几个轮子准备好了，大多难题都已解决，该组装了。</p><h3 data-omnivore-anchor-idx="127">下载并筛选新闻</h3><p data-omnivore-anchor-idx="128">先组装出核心任务，它能从单个新闻源下载新闻，筛选后保存为文本文件，完成整个程序里绝大多数工序。</p><p data-omnivore-anchor-idx="129"><strong data-omnivore-anchor-idx="130">输入：新闻源地址、详情页正文所在 HTML 标签</strong><br data-omnivore-anchor-idx="131"><strong data-omnivore-anchor-idx="149">优先级问题</h3><p data-omnivore-anchor-idx="150">调试核心任务的过程中，很多次出现取不到内容的情况，卡了很久。深入研究找到了原因：原来子任务的执行竟然是并行的！</p><p data-omnivore-anchor-idx="151">Tasker 的灵魂是它的 Perform Task，作用是在当前任务里执行一个子任务。执行时可以把当前任务的信息传递给子任务，并获得子任务处理后的结果。</p><p data-omnivore-anchor-idx="152">传入参数，获得返回值，这不就是编程里的函数吗？虽然 Tasker 有限制，最多只能往子任务里传 2 个参数，但如果把多个参数用特定分隔符拼接成字符串，传到子任务里再拆分开，理论上多少个参数都能传进来。用这种结构层层嵌套，什么复杂的逻辑做不出来？Perform Task 的存在，使 Tasker 成为一款编程软件。</p><figure data-omnivore-anchor-idx="153"><img data-omnivore-anchor-idx="154" data-omnivore-original-src="https://cdnfile.sspai.com/2024/08/13/article/7e5dabd35be1c359d3e77e4ba0efe68c.jpeg?imageView2/2/format/webp" src="https://proxy-prod.omnivore-image-cache.app/0x0,sshk4zaHuz0m6daeWuHOigPMglrPyCpQJZGsQBaMinAE/https://cdnfile.sspai.com/2024/08/13/article/7e5dabd35be1c359d3e77e4ba0efe68c.jpeg?imageView2/2/format/webp" data-original="https://cdnfile.sspai.com/2024/08/13/article/7e5dabd35be1c359d3e77e4ba0efe68c.jpeg?imageView2/2/format/webp" data-index="14"></figure><p data-omnivore-anchor-idx="155">仔细阅读了 Perform Task 的帮助文档，里面提到了执行顺序问题。触发子任务时，外层任务并不会等子任务执行完再继续（我一直这么以为），而是并行执行下去了。我的程序中，许多子任务要去网上获取内容，或对页面代码进行大量的循环处理，耗费时间很长。在子任务给出处理结果前，外层任务继续执行，当然就接不上了。</p><figure data-omnivore-anchor-idx="156"><img data-omnivore-anchor-idx="157" data-omnivore-original-src="https://cdnfile.sspai.com/2024/08/13/article/a61f89ec867963306c536eb3a87498fe.jpeg?imageView2/2/format/webp"
